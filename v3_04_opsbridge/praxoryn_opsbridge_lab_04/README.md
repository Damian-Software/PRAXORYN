# PRAXORYN OpsBridge — hands-on lab 04

Native Debian 13 / WSL2 educational reference. No Docker; no Boost.

## First run

```bash
cd praxoryn_opsbridge_lab_04
python3 -m venv .venv
source .venv/bin/activate
export OPSBRIDGE_HOME="$PWD/.private-data"
python -m opsbridge init
python -m opsbridge create --tenant demo_acme --kind summary --input examples/summary.json
python -m opsbridge worker-once
python -m opsbridge list --tenant demo_acme
python -m opsbridge verify-audit
```

Copy the `job_id` shown by `create`, then use `approve` followed by `release` after inspecting the output. This is an *offline fixture*, not real inference. A local server with `/v1/chat/completions` can be connected via `worker-once --backend llm --base ... --model ...`.

## What is and is not secure here

- The SQLite file stores request payloads in plaintext. Never use customer data for the unmodified lab.
- The CLI has no user authentication; `--tenant` is a filter, not an authorization control.
- SHA-256 audit chaining detects some modifications but does not stop a database administrator from rewriting the whole chain.
- The `released` state does **not** publish to the internet. Export requires a separate controlled step.
- Multi-tenant production requires an authenticated API, tenant authorization in every query, encrypted storage, quotas, separate secrets management, robust transaction handling, and a security review.
- ComfyUI API submission requires a trusted API-format workflow and a server bound to loopback. No image/video will be generated by the offline mode.

## Troubleshooting

- `queue_empty`: no pending job or job is leased; inspect the DB with a local privileged operator.
- `wrong current state`: use `list` and check that the job went from `queued` → `review` first.
- `url` rejected: deliberately only loopback HTTP endpoints are allowed in this lab.
- unexpected import errors: run from project root or install the package into `.venv` explicitly.

## Sector exercise library

The `examples/case_*.json` files are synthetic only. Supported kinds:
`summary`, `document`, `code_review`, `image`.

```bash
python -m opsbridge create --tenant demo_books --kind document \
  --input examples/case_accounting.json
python -m opsbridge worker-once
python -m tools.invoice_check --csv examples/invoice.csv \
  --expected 309.70 --output invoice-report.json
python -m tools.claim_packet examples/claim.json
python -m tools.school_acl
```

The offline `code_review` is a deliberately weak keyword exercise. It is not a
replacement for Ruff or clang-tidy; the earlier CodeOps lab contains the
scanner and SARIF examples. The offline `image` task is a marker, **not AI image
synthesis**. Live ComfyUI use requires an approved API-format workflow.

## State model

`queued` → `running` → `review` → `approved` → `released`; a reviewed job may
instead become `rejected`. The `released` state marks approval only; there is
no automatic internet publication or outbound customer messaging.

## Review before production

CLI actors are self-reported and there is no authenticated API. Requests and
artifacts may contain plaintext. A production deployment needs genuine identity,
resource authorization, key rotation, at-rest protection and separation of
operators from reviewers. Do not install this exact fixture as a public SaaS.
